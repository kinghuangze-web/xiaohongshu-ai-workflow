# 用 AI 做小红书：用了什么工具，具体怎么做

这是一个知识科普账号的实际工作流程：**我在飞书确认选题，Codex 调用工具写稿、做图、整理文件，再把内容填进小红书发布页，最后由我审核并点击发布。**

## 用了哪些工具

| 工具 | 它是什么 | 在这个项目里做什么 |
|---|---|---|
| **飞书多维表格** | 一张能记录审核状态的在线表 | 放选题、资料来源、计划时间；我把要做的题标为“通过” |
| **Codex** | 能读写电脑文件、运行脚本和调用工具的 AI 助手 | 读取选题和规则，调用下面的工具，整理文件，准备发布页面 |
| **Antigravity CLI** | 本项目使用的命令行 AI 工具，可由脚本调用 | 根据选题查资料，写标题、正文、标签和每一页要放的文字 |
| **GPT 生图工具** | 按文字和参考图生成图片的工具 | 生成封面、内容页和尾图；这次试跑由 Codex 直接调用内置 `image_gen` 完成 |
| **Easel** | 运行在本地的内容管理网页 | 查看文案、图片和日历排期，复制要使用的内容 |
| **Chrome＋浏览器控制扩展** | 把浏览器页面操作交给 Codex 的连接方式 | 打开已登录的小红书创作者中心，上传图片、填写文案和时间 |

**Codex 负责把操作接起来，Antigravity 写稿，GPT 画图，Easel 展示结果，Chrome 负责进入发布页面。**

## 一篇内容按什么顺序做

![小红书内容制作流程：每步标明工具、操作和结果](assets/项目工作流程图.png)

| 步骤 | 具体操作 | 做完得到什么 |
|---|---|---|
| **1. 选题** | 我在飞书审核题目和资料，确定日期、时刻；Codex 读取通过的条目 | 一条确定要制作的选题 |
| **2. 写稿** | Codex 通过项目脚本调用 Antigravity，按固定要求写稿 | 平台用的标题、正文、标签；每一页图片的文字和画面说明 |
| **3. 做图** | Codex 把文案、参考图和生图规范交给 GPT 生图工具，逐张生成并检查 | 封面和需要的内容页，每页一个图片文件 |
| **4. 收好文件** | Codex 核对图片和文案是否属于同一篇，按顺序放进日期文件夹；在 Easel 里查看 | 一篇文案＋排好顺序的图片＋计划时间 |
| **5. 填发布页** | Codex 控制 Chrome 上传素材，填标题、正文、话题、声明和时间，再读回检查 | 一张已经填好、尚未提交的编辑页面 |
| **6. 人工发布** | 我检查图文、事实、声明和时间，亲自点击发布或定时发布 | 平台确认的发布或定时结果 |

这里保留两处人工判断：**选题审核，以及最终审核与发布。** 有错误的文案或图片先修改，不直接带到发布页。填好了定时时间，也要等人提交、平台确认后才算定时成功。

## 这些工具为什么知道要怎么做

我把固定要求写成规则文件，交给 Codex 和相应工具读取。例如：正文怎么写、套图分几页、图片比例、文件放哪里、不能点击发布按钮。

这类可重复使用的说明通常叫 **Skill（技能）**。它是一份任务说明，不是另一款制作软件。生图用的通用要求见[生图经验](03-生图经验与通用规范.md)。

## 想自己试，先做哪一步

先用自己的一篇内容做完“写稿 → 生图 → 文件放在一起 → 手工上传”。能完成一篇，再让 Codex 接手文件整理和浏览器填写。具体操作见[从零尝试指南](02-从零复现指南.md)，每一步如何交接见[完整步骤](01-完整方案.md)。

视频是额外步骤：把同一份图卡和文案放进 **Remotion 模板**生成 MP4，用 **FFmpeg** 检查文件，再进入上面的第 4 步。只做图文时不用这两个工具。

本仓库公开方法、流程图和[Python 组包练习](examples/README.md)，没有附带原生产系统的全部脚本和账号配置。示例代码只练习本地整理文件，不能一键运行上述整套流程。

此前也使用过网页版 ChatGPT 做图；图中说明的是已核验的 Codex 内置生图路线。仅在网页里使用 ChatGPT 时，需要自己附上规范与参考图，下载图片。
