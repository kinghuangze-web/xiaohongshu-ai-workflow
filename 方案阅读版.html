用 AI 做小红书：用了什么工具，具体怎么做

这是一个知识科普账号的实际工作流程：我在飞书确认选题，Codex 调用工具写稿、做图、整理文件，再把内容填进小红书发布页，最后由我审核并点击发布。

用了哪些工具

工具 它是什么 在这个项目里做什么
飞书多维表格 一张能记录审核状态的在线表 放选题、资料来源、计划时间；我把要做的题标为“通过”
Codex 能读写电脑文件、运行脚本和调用工具的 AI 助手 读取选题和规则，调用下面的工具，整理文件，准备发布页面
Antigravity CLI 本项目使用的命令行 AI 工具，可由脚本调用 根据选题查资料，写标题、正文、标签和每一页要放的文字
GPT 生图工具 按文字和参考图生成图片的工具 生成封面、内容页和尾图；这次试跑由 Codex 直接调用内置 image_gen 完成
Easel 运行在本地的内容管理网页 查看文案、图片和日历排期，复制要使用的内容
Chrome＋浏览器控制扩展 把浏览器页面操作交给 Codex 的连接方式 打开已登录的小红书创作者中心，上传图片、填写文案和时间

Codex 负责把操作接起来，Antigravity 写稿，GPT 画图，Easel 展示结果，Chrome 负责进入发布页面。

一篇内容按什么顺序做

步骤 具体操作 做完得到什么
1. 选题 我在飞书审核题目和资料，确定日期、时刻；Codex 读取通过的条目 一条确定要制作的选题
2. 写稿 Codex 通过项目脚本调用 Antigravity，按固定要求写稿 平台用的标题、正文、标签；每一页图片的文字和画面说明
3. 做图 Codex 把文案、参考图和生图规范交给 GPT 生图工具，逐张生成并检查 封面和需要的内容页，每页一个图片文件
4. 收好文件 Codex 核对图片和文案是否属于同一篇，按顺序放进日期文件夹；在 Easel 里查看 一篇文案＋排好顺序的图片＋计划时间
5. 填发布页 Codex 控制 Chrome 上传素材，填标题、正文、话题、声明和时间，再读回检查 一张已经填好、尚未提交的编辑页面
6. 人工发布 我检查图文、事实、声明和时间，亲自点击发布或定时发布 平台确认的发布或定时结果

这里保留两处人工判断：选题审核，以及最终审核与发布。 有错误的文案或图片先修改，不直接带到发布页。填好了定时时间，也要等人提交、平台确认后才算定时成功。

这些工具为什么知道要怎么做

我把固定要求写成规则文件，交给 Codex 和相应工具读取。例如：正文怎么写、套图分几页、图片比例、文件放哪里、不能点击发布按钮。

这类可重复使用的说明通常叫 Skill（技能）。它是一份任务说明，不是另一款制作软件。生图用的通用要求见生图经验。

想自己试，先做哪一步

先用自己的一篇内容做完“写稿 → 生图 → 文件放在一起 → 手工上传”。能完成一篇，再让 Codex 接手文件整理和浏览器填写。具体操作见从零尝试指南，每一步如何交接见完整步骤。

视频是额外步骤：把同一份图卡和文案放进 Remotion 模板生成 MP4，用 FFmpeg 检查文件，再进入上面的第 4 步。只做图文时不用这两个工具。

此前也使用过网页版 ChatGPT 做图；图中说明的是已核验的 Codex 内置生图路线。仅在网页里使用 ChatGPT 时，需要自己附上规范与参考图，下载图片。

离线阅读版需下载后用浏览器打开。公开范围与许可证。

一篇小红书内容，具体怎样从选题做到发布

先看工具表和总流程图。下面只讲每一步实际交给谁、交什么、怎么接到下一步。

1. 我在飞书选题，Codex 读取审核结果

飞书多维表格里记录题目、资料来源、审核结论和计划时间。我检查题材和资料，把要制作的条目标成“通过”。

开始制作时，Codex 运行本地脚本读取这些条目。未通过的题不进入制作；已有图片或我正在处理的内容先保留。

交给下一步：选题、资料、发布日期和时刻。

2. Codex 调用 Antigravity，写出文案和逐页说明

Antigravity CLI 是这里负责查资料和写稿的 AI 工具。CLI 表示它能从命令行启动，因此 Codex 可以通过脚本调用它。

写稿时同时交出两类内容：

  • 发布文案：放进小红书正文栏的标题、正文和标签。
  • 逐页制图说明：封面写什么、各内容页写什么、画面需要展示什么。

一篇多语言内容的详细文字放在同一份说明里，按语言分好页。研究来源和未确定的问题另留给审核，不塞进公开正文。

交给下一步：逐页制图说明、参考图和生图规则。发布文案先保存在本地。

3. Codex 调用 GPT 生图，逐张做出图片

这次已核验的制作使用 Codex 内置 image_gen。Codex 将上一步的说明和参考图交给它，图片生成后保存在电脑上。

先做封面。封面中的实物、文字和版式检查通过后，再把它作为参考，制作其他页面，保持全套是同一件物品。

如果采用“封面＋四种语言各一页＋尾图”，就要得到六张独立图片。图上的术语、日期、编号和物件结构要检查；发现错误就修正对应页。

交给下一步：一组内容正确、数量齐全的图片文件。

4. Codex 整理文件，我在 Easel 里查看

Codex 按图片内容和编号找到对应文案，检查页数和顺序，把它们放进日期下各篇自己的文件夹。

用通用名称表示，文件大致如下：

某一天/
  第1篇/
    发布包.txt          标题、正文、标签
    制图说明.txt        每页文字和画面要求
    images/
      01_封面.png
      02_内容页.png
      ...

这里的“制图说明.txt”是便于理解的通用名称；实际多语言内容使用“多语言发布包.txt”。上传正文用“发布包.txt”，不能把整份制图说明粘到正文栏里。

Easel 是本地网页工作台，用来查看这些内容和日历排期。它提供查看、预览和复制入口；本地脚本负责实际整理文件。

交给下一步：本篇文案、有序图片列表和明确的计划时间。

5. Codex 操作 Chrome，把内容填进发布页面

Chrome 通过浏览器控制扩展连接到 Codex。本人先登录正确的小红书账号；Codex 再操作已经登录的创作者中心。

它按上一步的材料，依次上传图片、填写标题和正文、选择正式话题、处理内容声明、填写日期时刻。最后重新读取页面，和本地文案及图片清单比较。

本次跑通的是这条 Chrome 扩展控制路线，没有调用第三方小红书 MCP 的发布接口。

交给我：已填好但未提交的页面。最终发布按钮不点。

6. 我审核，再亲自发布

我在页面上检查图片顺序、文案事实、话题、原创与 AI 声明，以及发布时间。有问题就退回前面的对应步骤修改。

检查完成后，由我亲自点击发布或定时发布。等平台确认，再登记实际状态。

本项目必须保留人工审核和最终发布，不做无人托管账号。 自动化做到发布前准备；“页面填好”与“平台已发布”是两个不同结果。

有定时维护任务负责补文案、检查缺项和保护已有内容；生图与浏览器代填也可以按批次交给 Codex 执行。当前有些文案任务仍会失败，因此这里说明各步骤怎样配合，不把它描述成永不出错的后台服务。

用自己的一篇内容试一遍

第一次先用已有的 AI 写稿、做图，手工上传。跑完一篇以后，再逐步让 Codex 代做重复操作。

1. 在飞书建一张选题表

只需要先建这几列：题目、资料来源、审核结论、计划时间。挑一个自己能核实的问题，填好资料，将审核结论改成“通过”。

原项目的脚本会读取飞书。自己初次尝试时，先把这一行复制给 AI 即可，不用先开发表格接口。

2. 让 AI 同时写发布文案和制图说明

原项目使用 Antigravity CLI；第一次也可以先在自己已有的 AI 聊天里输入：

我要做一篇知识科普小红书内容。
选题：[你的题目]
已核实资料：[你的资料]

请交给我两部分：
1. 发布文案：标题、正文、标签。
2. 制图说明：逐页列出图中文字和画面要求。

不确定的事实单独列出，先让我检查。

核对文字后，将发布文案保存为“发布包.txt”，将逐页说明另存。不要把研究备注放进发布正文。

3. 用 GPT 做图

把逐页说明、参考照片和生图规范一起交给图像工具。

有 Codex 内置生图工具时，可以让 Codex 逐页调用并保存图片；在 ChatGPT 网页里做时，就自己附上文件和参考图，下载成品。

先检查封面，再用封面做其他页的参考。每页保存成单独图片，按“01、02、03……”命名。检查物体有没有画错，字有没有漏，整套有没有换成另一件产品。

4. 把同一篇的文件放在一起

为这篇建一个文件夹，放入发布包、制图说明和 images 图片目录。可以让 Codex 帮你检查：

请检查这个文件夹中的发布文案和图片是否对应。
核对图片内容、页数、顺序及封面日期编号。
列出缺什么和错在哪里。保留原文件，不覆盖我的修改。

原项目会把结果显示在 Easel 的内容库和日历里。第一次用文件夹也能完成这一步；Easel 是查看和管理内容的网页界面。

5. 先手工完成一次发布页

登录自己的小红书创作者中心，上传图片，填标题正文，选择话题，按内容处理声明和时间。核对完成后自己提交。

确认这一步怎么操作后，如果你的 Codex 已连接 Chrome 浏览器工具，可以把重复填写交给它：

根据这个文件夹准备一篇小红书编辑页面。
先核对已登录账号，再按顺序上传素材，填写标题、正文、
正式话题、必要声明和计划时间。
填完后逐项读回比较，保留页面让我审核。
不要点击发布或定时发布按钮。

只安装 Chrome 不等于 Codex 已能控制它，需要在自己使用的工具中完成浏览器连接。最后仍由本人审核并点击提交。

6. 重复稳定后，再接定时任务

原项目由定时任务调用本地脚本，读取审核结果，补充缺少的文案，记录失败，保留已有图片和人工修改。

搭建自己的版本时，先让 Codex 完成一次明确的任务，再设置重复运行的时间。不要把“定时检查文案”设成“定时无人发布”。

本仓库能直接运行的是什么

附带的 Python 示例只练习“检查本地资料、按顺序复制图片、生成一份待审核的内容包”。安装 Python 3.10 或更新版本后，在仓库根目录运行：

python examples/prepare.py examples/sample.json

首次返回 ok: false 是预期结果：示例没有图片，也没有人工审核记录。按示例说明填自己的内容后再运行。

它没有连接飞书、Antigravity、生图或浏览器。完整自动化还要接入这些工具和相应脚本，本仓库没有提供一键安装原生产系统的程序。

做知识图卡时，我固定检查这几件事

这些经验来自生活物件科普图卡。可以把下面的要求存成文件，每次做图时交给工具读取；支持 Skill 的工具也可以将它作为技能说明使用。

1. 先说清楚物体长什么样

只给一个零件名字，模型容易画出“看起来像”的另一个东西。先提供实物照片，再写清楚：

  • 它装在哪个完整物件上，位于哪个位置。
  • 它连接什么，是一个还是多个。
  • 哪些孔、槽、边缘、折弯和比例不能改。
  • 什么材质，处于使用、包装还是拆开状态。

过去出现过一种错误：一个用于连接两件东西的零件，被画成只装在一件物品上的金属片。此时要修连接关系，继续要求“更精致”没有用。

2. 实物参考和风格参考分别说明

告诉模型：“参考图 A 决定物体结构，参考图 B 决定光线、背景和版式。”

实物照片背景不好看，也可以保留正确结构、重新安排摄影环境。不要为了画面好看，增加不存在的按钮、孔洞或装饰。

3. 一套图使用同一件物体

先生成封面，确认后再做第一张内容页。之后每一页都把封面作为物体参考，把第一张内容页作为版式参考。

全套保留相同的颜色、材料、轮廓和关键结构。可以改变裁切，但不能换一款产品，或把目标部件移到另一边。

4. 生成前就列好页数

例如四语言内容使用：封面、中文页、日语页、英语页、第四语言页、尾图，一共六张独立图片。

逐页生成并保存。不要把“六张图”做成一张六格拼图，也不要用同一张图裁六次来凑数。

单图笔记只做需要的那一张，不套用六页要求。

5. 图片上的字也要检查

术语、读音、例句先在文案里查清，再放进图片。不要让生图模型自行增加标准、专利、年份或数字。

需要日期和编号时，给出确切值，不让模型猜。生成后打开原图校对，再按手机大小看一次。字太多就删减内容或增加分页，不把字号一直缩小。

可以直接使用的制作说明

以下是通用模板，请替换方括号内容：

制作一张知识科普图片，只生成本页。

本页用途：[封面/内容页/尾图]
画幅：[例如竖版 3:4]
准确文字：[已经核对的文字]
日期和编号：[如需要，填确切值]

参考图 A：保留它的实物结构、位置、数量和比例。
参考图 B：参考它的背景、光线和文字排版。
不能改的结构：[具体列出]
允许调整：[背景、光线、裁切等]

后续页面沿用已通过封面的同一物体，不换型号和颜色。
不要新增未经确认的知识、品牌或结构。
文字放不下时先告诉我，不用很小的字强塞。

返工时指明具体问题，例如“保留版式，只把目标部件改回参考图中的连接方式”。已经正确的其他页不用全部重做。

本地教学示例：核验并整理一条内容

只使用 Python 标准库，不联网、不登录、不调用模型，不包含发布功能。它是重新编写的教学实现，不是原项目执行器。

它能做什么

  • 检查标题、正文、标签、完整时间与唯一页面角色。
  • 检查显式人工审核记录与本地 PNG/JPEG/WebP 素材文件头。
  • 计算文件 SHA-256，按清单顺序复制素材。
  • 输出发布包和待人工审核清单，始终记录 submitted: false。
  • 拒绝覆盖既有输出目录。

文件头检查不等于完整解码或视觉验收。脚本不会判断图中物体、事实、日期或编号是否正确；审核布尔值由人实际检查后填写。

运行环境

需要已安装的 Python 3.10 或更新版本。Windows 可先运行 py --version；没有 py 时用自己环境中的 python。安装来源、权限与路径按自己的设备选择。

在本 examples 文件夹打开终端：

py -3 .\prepare.py .\sample.json

初次返回 ok: false 和退出码 2 是预期结果：示例故意没有图片，也没有人工审核通过，避免把假数据当成可发布内容。

用自己的内容完成练习

  1. 复制 sample.json 为 my-note.json。
  2. 在 assets 文件夹放入自己的 PNG/JPEG/WebP 图，更新清单相对路径。不要使用别人的真实账号素材。
  3. 改成自己的编号、标题、正文、标签和完整时间。
  4. expected_roles 与素材角色一一对应。单图示例为 cover；多语言可改为 cover, cn, jp, en, other, tail。
  5. 逐项核实事实、素材身份与图片内容，完成后才把对应审核值设为 true。
  6. 再运行校验。成功后组包：
py -3 .\prepare.py .\my-note.json --out .\practice-output

成功只表示本地包已经准备，不表示允许直接发布。再次使用同一输出目录会拒绝覆盖；请检查已有内容，或者选择新的练习目录。

生成结果：

  发布包.txt
